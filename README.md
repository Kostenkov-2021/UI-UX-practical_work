# Инспектор доступности - расширение для проверки сайтов

Браузерное расширение для Chromium-браузеров, которое проверяет веб-страницы на распространённые проблемы доступности и формирует отчёты в нескольких форматах.
Проект реализуется на `HTML`, `CSS`, `JavaScript` как расширение Manifest V3 без отдельного бэкенда.

Основной акцент сделан на автоматизированной проверке доступности: контрастность текста и нетекстовых элементов, альтернативные тексты изображений, язык страницы, семантика, формы, ARIA-атрибуты, клавиатурная навигация, порядок фокуса, статусные сообщения и целостность ссылок на `id`.

## Общие данные и стиль

Параметры расширения:

* тип проекта: расширение для Chromium-браузеров;
* версия в `manifest.json`: `1.1`;
* версия в интерфейсе: `v1.1`;
* формат манифеста: Manifest V3;
* название расширения: `Инспектор доступности`;
* действие расширения: popup `popup/popup.html`;
* фоновый скрипт: `background.js`;
* основной проверяющий скрипт: `content-script.js`;
* поддерживаемые адреса проверки: `http://*/*` и `https://*/*`;
* разрешения: `activeTab`, `storage`, `scripting`.

Основные цвета интерфейса popup:

* общий фон: `#f6f7fb`;
* карточка интерфейса: `rgba(255,255,255,0.92)`;
* приглушённая поверхность: `#f3f4f6`;
* основной акцент: `#0a84ff`;
* акцент при нажатии: `#0767d1`;
* основной текст: `#11121a`;
* вторичный текст: `#667085`;
* успешное состояние: `#16a34a`;
* ошибка: `#ef4444`;
* предупреждение: `#f59e0b`.

Имитационные и рабочие данные:

* URL текущей вкладки подставляется автоматически, если адрес начинается с `http` или `https`;
* последний введённый URL сохраняется в `chrome.storage.local`;
* последний выбранный формат отчёта сохраняется в `chrome.storage.local`;
* дата скачиваемого файла берётся из `new Date().toISOString().slice(0,10)`;
* имя скачиваемого файла: `accessibility-report-ГГГГ-ММ-ДД.<расширение>`.

## Экраны и сценарии

### 1. Основной popup - `popup/popup.html`

Экран запуска проверки доступности.

На экране:

* заголовок `Инспектор доступности`;
* поле `URL-адрес сайта:`;
* подсказка `Введите полный URL-адрес сайта для проверки доступности`;
* список `Формат отчёта:`;
* подсказка `Выберите формат загрузки отчёта`;
* кнопка `Проверить доступность`;
* область статуса с `role="status"` и `aria-live="polite"`;
* блок `Результаты проверки`;
* сводка по количеству проблем, ошибок и предупреждений;
* кнопки `Скачать отчёт`, `Скопировать в буфер обмена`, `Просмотреть отчёт`;
* подпись версии `Инспектор доступности v1.1`.

Форматы отчёта:

* `JSON`;
* `HTML`;
* `Текст`;
* `Markdown`.

Правила:

* при открытии popup фокус устанавливается в поле URL;
* текущий URL активной вкладки подставляется автоматически;
* если URL пустой, показывается ошибка `Пожалуйста, введите URL-адрес для проверки`;
* если URL не начинается с `http://` или `https://`, показывается ошибка `Пожалуйста, введите действительный URL-адрес (http:// или https://)`;
* клавиша `Enter` в поле URL запускает проверку;
* во время проверки кнопка блокируется, текст меняется на `Проверка...`, показывается индикатор загрузки;
* после успешной проверки показывается сообщение `Проверка успешно завершена!`;
* при ошибке выполнения показывается сообщение с причиной сбоя.

Переходы и действия:

* `Проверить доступность` - отправляет сообщение `checkAccessibility` в `background.js`;
* `Скачать отчёт` - скачивает отчёт в выбранном формате;
* `Скопировать в буфер обмена` - копирует текущий отчёт;
* `Просмотреть отчёт` - открывает отдельное окно предпросмотра отчёта.

---

### 2. Фоновая проверка - `background.js`

Сценарий координации проверки сайта.

На этапе проверки:

* принимается сообщение `checkAccessibility`;
* валидируется URL;
* создаётся новая неактивная вкладка с проверяемым сайтом;
* расширение ждёт полной загрузки вкладки;
* во вкладку внедряются утилиты и `content-script.js`;
* проверяется готовность зависимостей;
* запускается функция `runA11yChecks`;
* формируется отчёт через `ReportGenerator`;
* вкладка проверки закрывается в блоке `finally`.

Правила:

* разрешены только адреса с протоколами `http:` и `https:`;
* ожидание загрузки вкладки ограничено 30 секундами;
* ожидание инициализации content script ограничено 10 секундами;
* готовность определяется по наличию `runA11yChecks`, `ColorUtils`, `A11yRules`, `ReportGenerator` и `window.a11yInspectorReady`;
* если проверка вернула данные без `issues` или `summary`, результат считается некорректным;
* если для не-HTML формата вместо отчёта получен HTML-документ, показывается ошибка о недоступном URL.

Переходы и действия:

* `checkAccessibility` из popup - запуск `handleAccessibilityCheck`;
* `performAccessibilityCheck` - запуск проверок в контексте страницы;
* `generateReportInContentScript` - генерация отчёта в контексте страницы;
* завершение проверки - возврат `{ report, format }` в popup.

---

### 3. Проверка страницы - `content-script.js`

Основной сценарий анализа DOM проверяемой страницы.

На этапе анализа:

* инициализируются зависимости;
* запускается общий набор правил из `A11yRuleUtils.runAllChecks`;
* выполняются дополнительные специализированные проверки;
* найденные проблемы собираются в массив `issues`;
* формируется сводка `summary`;
* результат возвращается в фоновый скрипт.

Категории проверок:

```text
images
language
language-parts
headings
forms
form-assistance
contrast
non-text-contrast
aria
keyboard
keyboard-traps
focus-order
semantics
navigation
links
interactive
syntax
page-title
text-spacing
hover-focus-content
label-in-name
status-messages
system
general
```

Правила:

* проверка не отправляет содержимое страницы во внешние сервисы;
* элементы без видимости не участвуют в части правил, где нужна визуальная проверка;
* для каждой проблемы сохраняются тип, категория, сообщение, селектор, фрагмент элемента и подробности;
* критичные нарушения помечаются как `error`;
* потенциальные проблемы и рекомендации помечаются как `warning`;
* системная ошибка проверки оформляется как проблема категории `system`.

---

### 4. Предпросмотр отчёта - `popup/report-popup.html`

Экран детального просмотра результатов.

На экране:

* заголовок `Предпросмотр отчёта о доступности сайта`;
* выбор формата отчёта;
* кнопка `Скачать`;
* блок `Общее`;
* ссылка на проверенный сайт;
* дата отчёта;
* счётчики всех проблем, предупреждений и ошибок;
* раздел `Подробности`;
* фильтр по типу проблемы;
* фильтр по категории;
* кнопка `Развернуть всё` или `Свернуть всё`;
* кнопки `Сбросить фильтры` и `Применить фильтры`;
* список найденных проблем.

Правила:

* каждая проблема отображается как раскрываемый блок `details`;
* проблемы можно фильтровать одновременно по типу и категории;
* кнопка разворачивания меняет состояние всех раскрываемых блоков;
* для проблем контраста показываются цвета, коэффициенты и рекомендации;
* для остальных проблем показываются подробности из поля `details`;
* при наличии справочных материалов добавляется блок `Материалы Doka`.

Переходы и действия:

* `Применить фильтры` - скрывает проблемы, которые не подходят под выбранные условия;
* `Сбросить фильтры` - возвращает полный список;
* `Развернуть всё` - раскрывает все проблемы;
* `Свернуть всё` - сворачивает все проблемы;
* `Скачать` - экспортирует отчёт в выбранном формате.

## Поддерживаемые проверки

### 1. Изображения

Проверяются:

* отсутствие атрибута `alt`;
* пустой `alt` у декоративного изображения;
* слишком длинный `alt` больше 125 символов.

Типы проблем:

* отсутствующий `alt` - ошибка;
* пустой или слишком длинный `alt` - предупреждение.

---

### 2. Контрастность текста

Проверяются:

* коэффициент контрастности по алгоритму WCAG;
* минимальный уровень AA;
* повышенный уровень AAA;
* размер шрифта;
* насыщенность шрифта;
* фактический цвет текста;
* фактический цвет фона;
* рекурсивное определение фона, если у элемента прозрачный фон.

Правила:

* обычный текст проверяется по требованию `4.5:1`;
* крупный или жирный крупный текст проверяется по требованию `3:1`;
* для проблемного цвета формируются рекомендации по затемнению или осветлению;
* в подробностях отчёта показываются текущий цвет, предлагаемый цвет и новый коэффициент контраста.

---

### 3. Контрастность нетекстовой информации

Проверяются:

* границы интерактивных элементов;
* индикаторы фокуса;
* SVG-графика;
* элементы с ролью `img`;
* управляющие элементы, где цвет помогает понять границы или состояние.

Правила:

* нетекстовые визуальные элементы проверяются по минимальному отношению `3:1`;
* в отчёте указывается, какой цвет создаёт проблему: граница, обводка, тень, графика или фон.

---

### 4. Язык страницы и частей контента

Проверяются:

* наличие `lang` у элемента `html`;
* корректность базового языка страницы;
* фрагменты текста, язык которых отличается от языка страницы;
* наличие отдельного `lang` у таких фрагментов.

Правила:

* определение языка выполняется локально в браузере;
* для коротких и неоднозначных фрагментов проверка снижает уверенность;
* если язык фрагмента отличается от языка страницы и у фрагмента нет собственного `lang`, создаётся предупреждение.

---

### 5. Заголовки и заголовок страницы

Проверяются:

* наличие `h1`;
* порядок заголовков `h1-h6`;
* наличие тега `title`;
* информативность заголовка страницы.

Правила:

* отсутствие `title` считается ошибкой;
* неинформативные значения вроде `document`, `untitled`, `page` считаются предупреждением;
* пропуск уровней заголовков считается предупреждением.

---

### 6. Формы и помощь при вводе

Проверяются:

* связанные подписи у `input`, `select`, `textarea`;
* обязательные поля без явной инструкции;
* корректность `autocomplete`;
* ограничения ввода без подсказки о формате;
* `aria-describedby`;
* `aria-errormessage`;
* `aria-invalid`;
* связь ошибок с конкретными полями;
* глобальные сообщения об ошибках.

Правила:

* поле без подписи считается ошибкой;
* `aria-describedby` и `aria-errormessage`, которые ссылаются на несуществующие элементы, считаются ошибками;
* визуальная ошибка без `aria-invalid="true"` считается ошибкой;
* обязательное поле без инструкции считается предупреждением;
* поле с ограничением ввода без подсказки считается предупреждением.

---

### 7. ARIA-атрибуты

Проверяются:

* элементы с `aria-label`;
* валидность ARIA-ролей;
* ссылки `aria-labelledby`, `aria-describedby`, `aria-controls`, `aria-activedescendant`, `aria-errormessage`;
* пустые и битые IDREF-ссылки;
* соответствие видимой метки доступному имени.

Правила:

* недопустимая ARIA-роль считается предупреждением;
* битая ссылка на `id` считается ошибкой;
* видимая метка, которая не входит в доступное имя, считается предупреждением.

---

### 8. Клавиатурная навигация и порядок фокуса

Проверяются:

* значения `tabindex`;
* интерактивные элементы, которые могут быть недоступны с клавиатуры;
* положительный `tabindex`;
* подозрительный порядок фокуса;
* потенциальные клавиатурные ловушки;
* перехват `Tab` и `Shift+Tab` без понятного выхода.

Правила:

* некорректное значение `tabindex` считается ошибкой;
* положительный `tabindex` считается предупреждением;
* возможная клавиатурная ловушка считается предупреждением;
* интерактивный элемент без клавиатурного доступа считается предупреждением.

---

### 9. Навигация

Проверяются:

* ссылки для пропуска навигации;
* семантические ориентиры `main`, `nav`, `header`, `footer`, `aside`;
* активные пункты навигации;
* корректность `aria-current`;
* случаи, когда для текущей ссылки используется `aria-selected` вместо `aria-current`.

Правила:

* отсутствие ссылок пропуска навигации считается предупреждением;
* отсутствие семантических ориентиров считается предупреждением;
* пустой `aria-current` считается ошибкой;
* нестандартное значение `aria-current` считается предупреждением;
* активный пункт без `aria-current` считается предупреждением.

---

### 10. Семантика и интерактивные элементы

Проверяются:

* интерактивные `div`;
* `div[onclick]`;
* `div[role="button"]`;
* таблицы, которые могут использоваться для вёрстки;
* кнопки без текстовой подписи;
* ссылки без текста;
* ссылки с неинформативным текстом.

Правила:

* кнопка без доступного имени считается ошибкой;
* ссылка без текстового содержимого считается ошибкой;
* интерактивный `div` вместо `button` считается предупреждением;
* вероятная таблица для вёрстки считается предупреждением.

---

### 11. Динамический и всплывающий контент

Проверяются:

* `aria-live`;
* `role="alert"`;
* `role="status"`;
* статусные сообщения без динамической области;
* live regions, скрытые через `aria-hidden`;
* всплывающий контент при наведении и фокусе;
* возможность закрыть всплывающий контент;
* устойчивость интерфейса к увеличенным интервалам текста.

Правила:

* статусное сообщение без live region считается предупреждением;
* live region, скрытая от вспомогательных технологий, считается ошибкой;
* ошибка, которая не объявляется в assertive-режиме, считается предупреждением;
* всплывающий контент без видимого способа закрытия считается предупреждением.

---

### 12. Синтаксис и целостность ссылок

Проверяются:

* пустые `id`;
* `id` с пробельными символами;
* дублирующиеся `id`;
* `label[for]`;
* `input[list]`;
* `headers` у ячеек таблиц;
* якорные ссылки на фрагменты страницы;
* ARIA-ссылки на `id`.

Правила:

* пустой `id` считается ошибкой;
* `id` с пробелами считается ошибкой;
* дублирующийся `id` считается ошибкой;
* ссылка на несуществующий `id` считается ошибкой;
* якорная ссылка на несуществующий фрагмент считается предупреждением.

## Форматы отчётов

### JSON

Формат для программной обработки.

Структура:

```json
{
  "url": "https://example.com",
  "timestamp": "2026-06-15T10:30:00.000Z",
  "issues": [
    {
      "type": "error",
      "category": "contrast",

        "ratio": "3.20",
        "requiredRatio": 4.5,

        }
      ]
    }
  ],
  "summary": {
    "total": 1,
    "errors": 1,
    "warnings": 0
  }

```

### HTML

Формат для визуального просмотра.

В отчёте:

* отдельный HTML-документ с `lang="ru"`;
* сводка с URL, датой и счётчиками;
* карточки проблем;
* цветовое разделение ошибок и предупреждений;
* селекторы и фрагменты HTML;
* подробности проверки;
* ссылки на материалы Doka.

### Текст

Формат для быстрого чтения и вставки в текстовые редакторы.

В отчёте:

* заголовок `ОТЧЁТ О ДОСТУПНОСТИ`;
* URL;
* дата;
* сводка;
* нумерованный список проблем;
* селекторы, код элемента, подробности и материалы Doka.

### Markdown

Формат для задач, документации и репозиториев.

В отчёте:

* заголовок `Отчёт о доступности сайта`;
* раздел `Сводка`;
* раздел `Детализация ошибок`;
* блоки по каждой проблеме;
* подробности контраста;
* код элемента в fenced code block;
* ссылки на материалы Doka.

## Установка и запуск

### Установка из исходного кода

1. Откройте браузер Chrome, Edge, Brave или другой Chromium-браузер.
2. Перейдите на страницу `chrome://extensions/`.
3. Включите режим разработчика.
4. Нажмите `Загрузить распакованное расширение`.
5. Выберите папку `UI-UX-practical_work/accessibility-inspector`.
6. После установки откройте popup расширения через иконку в панели браузера.

### Использование

1. Откройте popup расширения.
2. Проверьте автоматически подставленный URL или введите другой адрес.
3. Выберите формат отчёта.
4. Нажмите `Проверить доступность`.
5. Дождитесь завершения анализа.
6. Просмотрите сводку.
7. Откройте подробный отчёт, скачайте файл или скопируйте результат в буфер обмена.

## Доступность интерфейса расширения

В интерфейсе расширения используются общие подходы:

* у страниц popup и предпросмотра указан `lang="ru"`;
* основной экран имеет заголовок `h1`;
* основной контент находится внутри `main`;
* служебные области размечены через `header`, `main`, `footer`;
* поле URL связано с `label`;
* поле URL имеет `aria-required="true"`;
* подсказка URL связана через `aria-describedby`;
* выбор формата связан с `label`;
* статус проверки размечен через `role="status"`;
* статус проверки использует `aria-live="polite"` и `aria-atomic="true"`;
* индикатор загрузки скрыт от вспомогательных технологий через `aria-hidden="true"`;
* результаты проверки находятся в `section` с `aria-labelledby`;
* кнопки имеют видимые текстовые названия;
* ошибки и успешные состояния показываются текстом, а не только цветом.

## История изменений

Текущая версия `1.1` расширяет базовую функциональность:

* добавлены проверки по WCAG и ГОСТ Р 52872-2019;
* добавлены проверки заголовка страницы;
* добавлена проверка `autocomplete`;
* добавлена проверка помощи при ошибках в формах;
* добавлена проверка контраста нетекстовой информации;
* добавлены проверки интервалов текста, всплывающего контента, порядка фокуса и клавиатурных ловушек;
* добавлена проверка соответствия видимой метки доступному имени;
* добавлена проверка статусных сообщений;
* добавлена проверка целостности ID-ссылок;
* добавлена проверка `aria-current`;
* добавлена локальная проверка языка отдельных частей контента;
* добавлены ссылки на материалы Doka;
* добавлен экспорт Markdown.

Подробное описание версий находится в `CHANGELOG.md`.
